# Contributing to Sparkience AI

Thank you for improving a Sparkience project. Repositories may range from prototype to production, so read the repository README and maturity declaration before proposing work.

## Before opening a pull request

1. Search existing issues and pull requests.
2. Open an issue before a large feature, architecture change, or user-data change.
3. Keep the change focused and preserve unrelated work.
4. Never commit credentials, private data, generated user content, or unlicensed datasets.
5. Add or update tests for behavior changes.
6. Update documentation when setup, behavior, limitations, privacy, or operations change.
7. Add an architecture decision record for a durable cross-cutting decision.

## Development workflow

- Create a short-lived branch from the repository's default branch.
- Use the repository's locked dependency installation and documented validation command.
- Run formatting, linting, type checks, tests, and builds locally when available.
- Submit a pull request using the provided template.
- Address review comments and keep required checks passing.

AI-assisted contributions are welcome, but the contributor remains responsible for correctness, licensing, security, tests, and every submitted line. Note material AI assistance in the pull request when it affected design or implementation.

## Reviews

Maintainers evaluate product fit, correctness, security, privacy, accessibility, documentation, and maintainability. A pull request may be declined even when it is technically valid if it conflicts with the repository's declared scope or maturity.

Security vulnerabilities must follow [SECURITY.md](SECURITY.md), not a public issue.
